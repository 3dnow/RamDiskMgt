通读 RamDiskKit、rdmctl 与 App 全部源码后的结论。本机没有 Swift 工具链，改动只经过人工核对，没有编译和跑测试；合并前请在 Mac 上执行 `swift test` 与 `--selftest apfs`。

## 1. 已修复的问题

| 严重度 | 位置 | 问题 | 处理 |
|---|---|---|---|
| 高（丢数据） | `ResizeService.resizeTmpfs` | 提权脚本 `umount -f → mount_tmpfs → chown` 在 umount 之后失败（例如 mount_tmpfs 出错）时，`originalGone` 仍为 false，catch 分支把暂存盘推出。此时原盘已卸载，暂存盘是唯一副本，数据全丢 | 失败后先检查原路径是否仍是 tmpfs 挂载点；原盘不在就保留暂存盘，错误信息给出暂存路径和释放命令，并记诊断日志 |
| 高（丢数据） | `ResizeService.resizeRamDevice` | 新盘已切到原路径并校验通过后，若释放旧设备或重新枚举失败，仍走回滚：拆掉已在用的新盘、挂回旧盘。切换之后写入的内容丢失，且用户看到“失败”却不知道盘已换回旧数据 | 校验通过后不再回滚：释放旧设备失败只记日志，枚举失败用已知信息拼出结果 |
| 高（安全） | `CleanupService.delete` | 越界检查用 `hasPrefix(rootPath)`，`/Volumes/Cache2/...` 会被当作 `/Volumes/Cache` 之内。卷内一个指向同名前缀目录的符号链接即可删到卷外 | 按路径分量比较（相等或以 `root/` 开头）；新增测试 `cleanupRefusesSiblingWithSamePrefix` |
| 中（丢配置） | `ProfileAutomationEditor` | 编辑器持有 profile 的 `@State` 副本，任意开关变动都整份回写。扩容后再点一下自动化开关，容量就被改回扩容前的值 | 新增 `AppModel.saveAutomation(from:)`，只合并自动化字段到最新配置 |
| 中 | `BackupService.create` | 文件名精确到秒，手动备份撞上定时备份会生成同名文件：后者覆盖前者，两条记录指向一个文件，删一条另一条也没了 | `uniqueDestination` 已存在时加序号；新增测试 |
| 中 | `AppDelegate.applicationShouldTerminate` | 扩容切换、还原进行中可以直接退出，盘停在半成品状态 | 有未完成操作时弹确认框，默认取消 |
| 中 | `AppModel.eject` | 设置了“推出 / 退出时备份”但钥匙串没有密码时，静默跳过备份直接推出 | 推出前提示“这次不会备份”，可取消；“自动化”面板在没有密码时显示警告 |
| 中 | `JSONFile.load` | `profiles.json` / `backups.json` 读不出来（损坏或新版本格式）时按空列表处理，下次保存直接覆盖原文件，全部配置和备份清单静默丢失 | 改名为 `*.corrupt-<时间>.json` 留档并记日志 |
| 低 | `rdmctl clean` | 不加 `--dry-run` 就直接永久删除，与 GUI“必须二次确认”的原则相悖 | 默认只列出，加 `--yes` 才删除；README 同步 |
| 低 | `DiskAnalyzer.hash` | 读文件中途出错返回半截内容的哈希，两个读失败的文件会被判为“内容相同”进入重复文件候选 | 读失败返回 nil |
| 低 | `Treemap.layout` | 极端权重比下剩余区域先于条目耗尽，继续摆放会除以 0 产生 NaN 矩形 | 剩余区域为 0 时停止；新增测试 |
| 低 | `AppModel.adopt` | 纳入管理时记的是卷容量而非设备大小，APFS 容器有开销，重建出的盘比原来小 | ram:// 盘按 `deviceBytes` 记 |
| 低 | `ResizeService.resizeTmpfs` | 暂存盘只留 96MB 余量；tmpfs 按页计量，大量小文件搬到 APFS 上元数据开销更大，可能同步到一半空间不足 | 按还原的推荐容量算法留 15% 余量 |
| 低 | `FileSync.copyItem` | ENOENT 重试后抛出的 errno 可能已被中间调用覆盖 | 显式保存 errno |
| 功能缺口 | `ProfileAutomationEditor` | README 写“备份目录每块盘可单独设置”，但界面上没有入口 | 增加“更改…”“恢复默认”按钮 |

## 2. 第二批修复（设计问题 1、2、3、5、6、12）

| 条目 | 处理 | 需要在 Mac 上验证的点 |
|---|---|---|
| 1 刷新开销 | 后台循环先取挂载表指纹（一次 `getfsstat`），没有卷挂上或卸下就不跑 `hdiutil`，只用 statfs 刷新已知盘；主窗口和菜单栏面板都不可见时间隔从 2 秒放宽到 15 秒，完整枚举兜底从 60 秒放宽到 300 秒；界面出现时立即刷新一次 | 关掉主窗口后 `ps` 观察不再每 5 秒出现 hdiutil；新建 / 推出盘后列表仍即时更新 |
| 2 提权阻塞主线程 | `InProcessAppleScriptExecutor` 改在专用串行队列上执行 `NSAppleScript`，主线程不再被 root 脚本卡住。`do shell script` 不向其他应用发 Apple 事件，不依赖主线程事件循环。设环境变量 `RDM_APPLESCRIPT_MAIN_THREAD=1` 可退回旧行为 | **必须重跑 `--selftest tmpfs`**：确认授权框正常弹出、取消授权仍被识别为取消（错误号 -128） |
| 3 切换瞬间的写入 | `TreeSummary` 增加全部文件 (路径, 大小, 修改时间秒) 的顺序无关指纹，复制保留修改时间，所以同大小的原地改写现在会让校验失败并回滚，不再静默丢失；扩容面板和占用进程提示都明说了这个窗口 | 集成测试里的扩容 / 缩容仍应通过（复制保留 mtime 到秒） |
| 5 大文件进度 | `FileSync.copyItem` 通过 `copyfile_state` 的状态回调拿到已复制字节数，≥ 4MB 的文件在复制中持续上报（最多每 0.1 秒一次）；扩容的操作条现在也显示“已处理 X / Y” | 扩容一块只有一个大文件的盘，进度条应连续移动 |
| 6 自动备份计时 | 只在新开启、间隔改变或关闭时才动对应盘的计时器；“自动化”面板显示上次自动备份时间和下次大约时间 | — |
| 12 rdmctl 参数 | `--force --yes --hidden --noexec --replace --dry-run` 不再吞掉后面的位置参数；支持 `--key=value` | — |

未处理的 4（硬链接）：同步仍逐文件复制，硬链接在新盘上成为独立副本。要保留需要按 inode 记录首次复制的目标再 `link()`，并发复制下要改成串行后处理，这次没有动。

## 3. 仍未改动的设计问题

1. **硬链接**：同步用 `copyfile` 逐文件复制，硬链接在新盘上变成独立副本，占用可能变大；校验按逻辑字节数比较所以能通过。
2. **钥匙串与 ad-hoc 签名**：每次重新构建后签名都变，访问已有钥匙串条目会反复弹出系统授权框。长期使用建议用固定的开发者证书签名。
3. **登录启动**：`SMAppService.mainApp` 对 `build/` 目录下的 ad-hoc 签名应用不一定能注册成功，失败时只弹提示。
4. **备份文件搬家**：清单里记的是绝对路径，备份目录移动后全部显示“缺失”，没有重新关联的入口（只能逐个导入）。
5. **外部盘名称**：`adopt` 不经过 `validate(name:)`，含 `'`、`$` 等字符的外部卷纳入管理后重建会被校验拒绝。
6. **调试入口随正式版发布**：`--selftest`、`--snapshot` 及两个探针都编译进了 Release 产物，建议用编译条件隔离。
7. **挂载选项不可修改**：nobrowse / noexec / Spotlight 只能在创建时选，之后要改只能重建。
