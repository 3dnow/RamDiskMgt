# 本地测试指南（2026-11 代码审查改动）

PR [3dnow/RamDiskMgt#1](https://github.com/3dnow/RamDiskMgt/pull/1) 的改动在没有 Swift 工具链的环境里完成，**没有编译过、没有跑过测试**。合并前按下面的顺序在 Mac 上过一遍。顺序是按“先便宜、先拦住编译错误”排的，前三步通不过就不用往后走。

每一步都写了：命令、预期结果、失败时大概率对应哪处改动。

## 0. 准备

```bash
git fetch origin claude/gifted-faraday-es7tx3
git checkout claude/gifted-faraday-es7tx3
rm -rf build Packages/RamDiskKit/.build
```

- macOS 27、Xcode 27（Swift 6.x）、`xcodegen`（`brew install xcodegen`）。
- 测试会创建名为 `RDMTest*`、`RDMSelfTest*` 的 RAM 盘，结束时自己推出。开始前确认 `diskutil list | grep -i ram` 里没有残留的同名盘。
- 单元测试用系统临时目录，必须在 APFS 上（克隆识别那组测试依赖 `clonefile`）。默认就是。

## 1. 单元测试（约 1 分钟）

```bash
cd Packages/RamDiskKit && swift test
```

预期：全部通过。原来 48 个测试，这次新增 6 个：

| 测试 | 验证的改动 | 失败时看哪里 |
|---|---|---|
| `cleanupRefusesSiblingWithSamePrefix` | 清理越界检查按路径分量比较 | `CleanupService.delete` |
| `sameSecondBackupsGetDistinctFileNames` | 同秒备份文件名加序号 | `BackupService.uniqueDestination` |
| `degenerateWeightsProduceFiniteRects` | treemap 极端权重不产生 NaN | `Treemap.layout` 的剩余区域守卫 |
| `summaryDetectsSameSizeRewrite` | 摘要指纹能区分同大小改写 | `TreeSummary.itemHash`；若这个失败，还要看 `FileSync.summary` 里 mtime 秒是否取对 |
| `progressIsMonotonicAndCompletes` | 大文件复制进度单调且最终等于总量 | `FileSync.copyItem` 的 `copyfile` 回调。**这里用了 C 函数指针 + `unsafeBitCast`，是本次最可能编译不过或崩溃的地方** |
| `hardLinksArePreserved` | 同步后目标端硬链接仍是同一 inode，二次同步不重复复制 | `FileSync.sync` 的 `linkJobs` 段 |

另外两个老测试要特别留意是否还过：`fullSyncThenIncremental` 末尾比较 `FileSync.summary` 相等（指纹依赖 copyfile 保留 mtime），`cleanupRefusesSymlinkEscape`（越界检查改法要兼容）。

编译失败而不是测试失败时，先把报错位置对照 `docs/代码审查-2026-11.md` 找到对应条目，大多只是签名或类型推断问题。

## 2. 集成测试（约 3–5 分钟，会建真实 ram:// 盘）

```bash
cd Packages/RamDiskKit && RDM_INTEGRATION=1 swift test
```

预期：3 组集成测试全部通过。这次改动影响到的点：

- **扩容 / 缩容校验**：现在校验多比一个修改时间指纹。如果出现“校验不一致：文件数和总大小都相同，但有文件在切换前的最后一刻被改写”，说明 `copyfile` 在 ram:// 盘之间没有把 mtime 保留到秒，需要把 `TreeSummary.itemHash` 里的秒改成更粗的粒度或去掉。正常情况下不会出现。
- **用户拒绝切换时回滚**：走的是 `verified == false` 的回滚分支，行为应与改动前一致。
- 硬链接、大文件进度在这组里也会被顺带覆盖（同步走的是同一段代码）。

结束后 `diskutil list | grep -i ram` 应该为空；有残留就 `diskutil eject diskN`。

## 3. Release 构建（约 2 分钟）

```bash
./scripts/build.sh
```

预期：成功，产物在 `build/RamDiskMgt.app` 和 `build/rdmctl`。这一步验证的是：

- App 目标在 Swift 6 严格并发下能过编译（`InProcessAppleScriptExecutor` 改成了 `@unchecked Sendable`、`AppModel` 新增的几个方法）。
- 诊断代码的空实现（`SelfTest.swift`、`DebugSnapshot.swift` 的 `#else` 分支）与调用点签名一致。

构建完顺手确认诊断入口确实没编进去：

```bash
strings build/RamDiskMgt.app/Contents/MacOS/RamDiskMgt | grep -c "SELFTEST PASSED"
```

预期输出 `0`。再执行 `build/RamDiskMgt.app/Contents/MacOS/RamDiskMgt --selftest apfs`，应该只是正常打开应用、不跑自检。

## 4. 带诊断入口的构建 + GUI 自检（约 3 分钟）

```bash
RDM_DIAGNOSTICS=1 ./scripts/build.sh
RDM_SUPPORT_DIR=/tmp/rdm-selftest build/RamDiskMgt.app/Contents/MacOS/RamDiskMgt --selftest apfs; echo "exit=$?"
```

预期：末尾打印 `SELFTEST PASSED`，`exit=0`，33 项 PASS。这条走的是 AppModel 层，覆盖创建、备份、扩容、分析、清理、推出、重建、还原。改动涉及到的：

- 扩容后 `check((resized?.deviceBytes ?? 0) == 512 MB)` 仍应通过（扩容成功路径没变）。
- 自检里的推出走 `force: true`，不会触发新增的“没有密码时提示”分支。

## 5. tmpfs 自检：验证提权脚本离开主线程（最重要，约 3 分钟，要输几次密码）

```bash
RDM_SUPPORT_DIR=/tmp/rdm-selftest build/RamDiskMgt.app/Contents/MacOS/RamDiskMgt --selftest tmpfs; echo "exit=$?"
```

`NSAppleScript` 从主线程移到了专用串行队列，这是行为变更。要确认三件事：

1. **授权框正常弹出**，输入密码后操作继续。末尾打印的 `提权调用 N：x.xx 秒` 每条应在 3–6 秒（含输密码时间），和测试报告里的数字一个量级。
2. **自检通过**：`SELFTEST PASSED`，21 项。
3. **取消授权仍被识别为取消**（自检不覆盖，手动做）：打开 App，新建一块 tmpfs 盘，授权框出现时点“取消”。预期：底部操作条显示“已取消授权”，**没有**红色错误提示框。如果弹出“创建失败”的错误框、内容是 `-128` 之类，说明后台线程上的错误码处理有问题。

如果第 1 条就不对（授权框不出现、进程卡住、或崩溃），先用回退开关确认是不是线程导致的：

```bash
RDM_APPLESCRIPT_MAIN_THREAD=1 RDM_SUPPORT_DIR=/tmp/rdm-selftest build/RamDiskMgt.app/Contents/MacOS/RamDiskMgt --selftest tmpfs
```

回退后能过，就是 `Privilege.swift` 里 `queue.async` 那段要改回主线程；回退后也不过，问题在别处。

## 6. 手动检查（界面行为，按改动逐项）

用第 4 步的产物。每项标了预计耗时。

### 6.1 刷新降频（2 分钟）

另开终端：

```bash
while true; do pgrep -x hdiutil >/dev/null && date '+%T hdiutil'; sleep 1; done
```

- 主窗口打开时：挂载表没变化就不应再看到 `hdiutil` 行（原来每 5 秒一次）。
- 关掉主窗口、菜单栏面板也收起：应几分钟都没有 `hdiutil`。
- 在另一个终端 `build/rdmctl create --name ExtTest --size 128M`：15 秒内菜单栏面板里应出现 `ExtTest`（挂载表变了，触发完整枚举）。然后 `build/rdmctl eject /Volumes/ExtTest`。

### 6.2 主线程不被提权卡住（1 分钟）

新建 tmpfs 盘，授权框弹出时不要输密码，去拖动主窗口、切换侧边栏。预期：窗口可以拖、可以点；原来会整个冻住。

### 6.3 大文件进度（2 分钟）

```bash
build/rdmctl create --name BigTest --size 2G
mkfile -n 1g /Volumes/BigTest/one.bin
```

在 App 里把 `BigTest` 调整容量到 4 GB。预期：底部操作条显示“已处理 X / Y”，数字在复制这一个文件期间连续变化，而不是从 0 直接跳到 1 GB。

### 6.4 切换瞬间改写能被发现（3 分钟，可选）

接上一步的盘。再开一个终端准备好但先不回车：

```bash
dd if=/dev/urandom of=/Volumes/BigTest/one.bin bs=1m count=1 conv=notrunc
```

发起扩容，看到阶段到“增量同步”或“检查占用进程”时回车执行。预期两种结果都算对：

- 校验失败，错误信息含“有文件在切换前的最后一刻被改写”，盘回滚到原盘、原盘可正常访问；
- 改写发生在增量同步之前，被同步带过去，扩容成功。

不应出现的：扩容成功但新盘上 `one.bin` 的内容不是改写后的（可用 `md5` 对比）。

### 6.5 硬链接（1 分钟）

```bash
echo hello > /Volumes/BigTest/a.txt
ln /Volumes/BigTest/a.txt /Volumes/BigTest/b.txt
```

扩容或缩容一次后：`ls -li /Volumes/BigTest/a.txt /Volumes/BigTest/b.txt` 两行 inode 相同。测完 `build/rdmctl eject /Volumes/BigTest`。

### 6.6 自动化面板不再覆盖容量（1 分钟）

新建一块 256 MB 的 APFS 盘并记住配置 → 调整容量到 512 MB → 回到“概览”，随便切一下“自动备份”开关。预期：

```bash
grep -A1 '"name"' ~/Library/Application\ Support/RamDiskMgt/profiles.json | grep sizeBytes
```

仍是 536870912（512 MB），不是 268435456。

同一面板里还应看到：没保存密码时的黄色警告；“上次自动备份 / 下次约”一行；“备份保存到”旁边的“更改…”按钮。

### 6.7 挂载选项修改（3 分钟）

- APFS 盘：概览 → 挂载选项 → 修改… → 勾“在 Finder 中隐藏” → 应用。预期：Finder 边栏里该盘消失，概览的挂载选项变成“在 Finder 中隐藏”；盘上文件仍在。再改回来。
- 勾“关闭 Spotlight 索引”：弹一次授权框，之后 `mdutil -s /Volumes/<盘>` 显示 disabled。再打开面板，Spotlight 开关应预先处于勾选状态（读的是 `mdutil -s`）。
- tmpfs 盘（已纳入管理）：改 nobrowse 后按钮文字应是“保存到配置”，点击后弹“已保存到配置，推出后重建时生效”，盘本身不变；`profiles.json` 里该盘的 `hidden` 已更新。
- 用 `rdmctl create --backend tmpfs` 建一块未纳入管理的 tmpfs：面板里两个标志开关应是禁用状态，并提示先纳入管理。

### 6.8 备份文件重新定位（2 分钟）

做一份备份 → 在 Finder 里把备份文件移到桌面 → 备份库里该条显示“缺失”，“重新定位…”按钮可用，指向桌面上的文件后恢复正常。再把整个 `Backups` 目录改名，备份库顶部出现“找回缺失的备份文件…”，选新目录后全部找回。

### 6.9 退出保护与推出提示（2 分钟）

- 开始一个备份，立刻 ⌘Q。预期弹“有操作正在进行”，默认按钮是“取消”。
- 给一块盘开自动备份并勾“推出 / 退出时备份”，但不保存密码，然后推出。预期弹“无法在推出前自动备份”，可取消。

### 6.10 rdmctl（1 分钟）

```bash
build/rdmctl create --name CliTest --size 128M
dd if=/dev/zero of=/Volumes/CliTest/big.bin bs=1m count=50
build/rdmctl clean /Volumes/CliTest --min-size 10M          # 只列出，末尾提示加 --yes
build/rdmctl clean /Volumes/CliTest --min-size 10M --yes    # 真删
build/rdmctl resize --yes /Volumes/CliTest --size=256M      # --yes 不吞掉挂载点，--size=值 可用
build/rdmctl eject /Volumes/CliTest
```

### 6.11 配置文件损坏时不丢（1 分钟）

退出 App，`echo '{broken' > ~/Library/Application\ Support/RamDiskMgt/profiles.json`，再启动。预期：目录里出现 `profiles.corrupt-<时间>.json`，`logs/store.log` 有一条记录，App 以空配置启动但没有覆盖原文件。测完把 corrupt 文件改回 `profiles.json`。

### 6.12 设置页登录项提示（半分钟）

设置 → 登录项。从 `build/` 目录运行时应看到黄色提示“应用不在‘应用程序’文件夹里”，旁边有“打开登录项设置”按钮。

## 7. 收尾

```bash
diskutil list | grep -i ram          # 应为空
rm -rf /tmp/rdm-selftest
```

钥匙串里自检留下的条目可以在“钥匙串访问”里搜 `RamDiskMgt` 清理。

## 8. 结果怎么反馈

把下面几样贴回来就够定位问题：

1. `swift test` 和 `RDM_INTEGRATION=1 swift test` 末尾的汇总行，失败的测试名和断言消息。
2. 构建失败时，`xcodebuild` 输出里第一处 `error:` 及其上下 5 行。
3. 两次自检末尾的 `SELFTEST ...` 行和 `提权调用` 耗时。
4. 第 6 节里不符合预期的项编号和实际现象。

第 5 步出问题最可能需要改代码，其余大多是文案或边角；都不影响第一批的那两处丢数据修复。
