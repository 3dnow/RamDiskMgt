# RamDiskMgt 设计文档

macOS 本机 RAM 磁盘管理工具：创建与管理、扩容（含运行中扩容）、加密备份（整盘或部分）、磁盘分析、大文件清理、还原/重建，提供 GUI 界面。

## 1. 参考项目调研

| 项目 | 类型 | 可借鉴 | 缺口 |
|---|---|---|---|
| [TmpDisk](https://github.com/imothee/tmpdisk)（GPL-3，2026-09 仍在更新） | 开源，Swift 菜单栏应用 | 同时支持 ram://（APFS/HFS+）和 TMPFS；特权 Helper + XPC；CLI；启动时自动创建；文件夹同步 | 不能扩容，没有加密备份，没有分析 |
| [SoftPerfect RAM Disk](https://softperfect.com/products/ramdisk) | 商业 | 动态分配、删除后回收内存、镜像持久化、关机自动保存 | 闭源 |
| ImDisk / Primo RAMDisk | Windows | 挂载中扩容、按需分配 | 只有 Windows |
| Ultra RAM Disk / RAMDisk Manager / OSX-RAMDisk / create-ram-disk | Mac 小工具 | 创建、备份、恢复 | 功能都很浅 |

本项目只参考思路，不拷 GPL 代码。

## 2. 本机实测结论（macOS 27.0 / M5 Max / 128GB）

| 问题 | 结论 | 证据 |
|---|---|---|
| ram:// 能否原地扩容 | **不能** | `hdiutil resize` 报 Invalid argument；`diskutil image resize` 报 “Operation is not supported for RAM disks” |
| tmpfs 能否原地扩容 | **不能**（会静默忽略） | `mount_tmpfs -o update -s 512m` 返回 0，但 df 显示大小不变；`mount -u -o size=` 报 “option not supported” |
| tmpfs update 的副作用 | 会**清掉 nobrowse** | update 之后 mount 标志只剩 `(tmpfs, local)` |
| tmpfs 权限 | 挂载需要 root | 普通用户执行 mount_tmpfs 报 Operation not permitted |
| tmpfs 卸载 | 必须加 force | fseventsd 一挂上就占住卷，普通 umount 报 Resource busy；先放 `.fseventsd/no_log` 也没用；`umount -f` 和 `diskutil unmount force` 可以 |
| tmpfs 上限 | 物理内存的 50% | `-s 1t` 被截到 68719476736（64GB） |
| tmpfs 内存 | 按需分配；删除后**延迟回收** | rm 后约 8 秒 df 仍显示 1500MB 已用，几分钟后归零 |
| ram:// 内存 | 按需分配；APFS 删除后**立即回收**；不是 wired 内存 | attach 2GB 后空闲内存没有掉 2GB；rm 1.5GB 后空闲内存回升约 2.4GB；wired 基本没变，压缩器有增长 |
| `hdiutil attach` | 已标记 deprecated | 提示改用 `diskutil image attach --noMount` |
| AEA 口令模式 | scrypt profile 要求密码 **≥ 20 字符** | 长度 8–19 时 setPassword 抛 invalidValue |
| 加密 DMG 转换 | `hdiutil convert` 不能处理加密源镜像 | 报 Permission denied |
| 加密 DMG 生成 | `diskutil image create from --encrypt --stdinpass --format ULFO <folder>` 可用 | 往返测试通过，错误密码报 Incorrect passphrase |
| `-srcfolder` 指定多次 | 每一项都放到镜像顶层，**原目录结构丢失** | man hdiutil |

## 3. 关键设计决策

### 3.1 双后端
- **APFS（ram://，默认）**：不需要 root；删除立即回收内存；卷可以卸载后挂到别的路径，扩容切换快。也支持 APFS（区分大小写）和 HFS+。
- **tmpfs**：内核原生，元数据操作快；但挂载、卸载都要管理员密码（用户选择了“每次弹密码框”）。通过 `osascript` 子进程执行（NSAppleScript 只能在主线程使用，在主线程同步执行会让界面冻结到 root 命令跑完）。实测 macOS 27 上**没有**“5 分钟授权缓存”，每次调用都会弹框，所以每个操作的 root 命令都合并成一个脚本：创建 1 次、推出 1 次、扩容 1 次。

### 3.2 扩容 = 热迁移
系统没有原地扩容的能力（见上表），所以统一做成“热迁移”：
1. 新建一块更大的盘，挂到隐藏的暂存路径；
2. **第一轮同步**：原盘照常读写，全量复制；
3. 检查哪些进程打开着原盘上的文件（lsof），展示给用户；
4. **第二轮增量同步**：只复制有变化的部分，耗时很短；
5. 切换：卸载原盘，把新盘挂到原路径；
   - APFS / HFS+：新盘直接卸载再挂到原路径即可，数据还在设备里；
   - tmpfs：tmpfs 不能换挂载点。暂存盘改用不需要 root 的 ram:// APFS 盘，切换时一次提权完成“卸载原盘 + 在原路径挂新 tmpfs”，再从暂存盘拷回（内存到内存）；
6. 校验文件数和总字节数，通过后才销毁旧盘；任何一步失败都回滚，旧盘保持不动。

同样的流程也能做**缩容**（新大小要大于已用空间）。代价：切换的瞬间，打开着旧盘文件的进程会失去文件句柄，所以第 3 步要把这些进程列出来。

### 3.3 加密备份
- **AEA（默认）**：用 AppleArchive 做 LZFSE 压缩 + AES-256-CTR + HMAC。密码先经 PBKDF2-SHA256（60 万次迭代）派生成 256 位密钥，再走 symmetric profile，这样绕开了 20 字符的限制。盐和 KDF 参数放在 AEA 头部的 `authData` 里（只做认证，不加密）。流式写入，部分备份用 select 回调过滤。
- **加密 DMG**：用 `diskutil image create from --encrypt --format ULFO`。部分备份先在**同一个卷里**用硬链接把选中的文件按原结构摆进暂存目录：不占额外内存，tmpfs 和 APFS 都支持。生成的镜像在 Finder 里输入密码就能挂载浏览。
- 备份目录、备份清单存在 `~/Library/Application Support/RamDiskMgt/`。密码可以选择存进登录钥匙串：每块盘存一条，供下次备份和自动备份使用；每份备份再按自己的 id 存一条，所以换过密码后旧备份仍能直接还原。
- 进度：AEA 统计 `encodeStream` 回调里的 `encodeWriting` 消息（实测约每 256KB 一次；`writeDirectoryContents` 的回调只在扫描阶段每个文件来一次）。DMG 解析 `diskutil image create` 写在 **stderr** 上的 `[NN% completed]`；硬链接暂存阶段按文件数报进度。备份窗口在整个过程中保持打开，显示阶段、已处理大小、速度，结束后显示结果或错误原文，可直接重试。

### 3.4 还原 / 重建
- 磁盘配置（Profile）持久化。“重建”就是按 Profile 新建盘，再把选中的备份（整份或部分）还原进去。
- 可选：应用启动时自动重建、自动还原最近一次备份、定时自动备份、退出时自动备份。

### 3.5 分析与清理
- 扫描生成目录树：按实际占用排序、按类型统计、最大文件、最大目录、长期未访问的文件、重复文件（先按大小分组，再算头部哈希，最后全量 SHA-256）。
- treemap（squarified 算法），可以点击下钻。
- 估算可释放空间时识别 APFS 克隆：读取 `ATTR_CMNEXT_PRIVATESIZE`（文件独占、不与克隆共享的字节数）。Finder 拷贝和 `FileManager.copyItem` 在 APFS 上默认都会生成克隆，删除克隆基本不释放空间。
- 清理：按规则勾选候选文件，可以先备份再删。RAM 盘没有废纸篓，删除就是永久删除，所以必须二次确认。tmpfs 删除后空间是延迟回收的，界面会说明。

## 4. 工程结构

```
RamDiskMgt/
├── project.yml                 # xcodegen：App 工程
├── App/                        # SwiftUI 应用（主窗口 + 菜单栏）
├── Packages/RamDiskKit/        # 核心逻辑，SwiftPM
│   ├── Sources/RamDiskKit/     # 后端、同步、备份、分析、清理、扩容
│   ├── Sources/rdmctl/         # 命令行工具（也用于端到端验证）
│   └── Tests/RamDiskKitTests/  # 单元测试 + 集成测试（RDM_INTEGRATION=1 才跑）
└── docs/
```

- 最低系统：macOS 27（本机），因为依赖 `diskutil image`。
- 签名：ad-hoc（用户不检查证书），不开沙盒。
